# Code review

Findings are ordered by impact. The existing tests and `cargo clippy --all-targets -- -D warnings` pass; the issues below concern behavior those checks do not cover.

1. **[High] Client-controlled forwarding headers can spoof identity and scheme** (`src/lib.rs:488-508`). `forward` appends to an incoming `X-Forwarded-For` rather than replacing it, preserves an incoming `X-Forwarded-Proto`, and copies `Host` into `X-Forwarded-Host`. A client sending `X-Forwarded-For: 127.0.0.1` or `X-Forwarded-Proto: https` can make an upstream that trusts the first forwarded address or scheme make authorization or secure-redirect decisions using attacker-supplied values. Strip untrusted forwarding headers at the trust boundary and construct them from verified proxy metadata; test forged headers end-to-end.

2. **[High] Database theft permits fast offline guessing of every pass phrase** (`src/users.rs:17-29`, `src/users.rs:74-78`). Unsalted, unkeyed SHA-512 is fast and deterministic, and whitespace removal reduces the candidate space. A leaked `users.db` allows inexpensive dictionary attacks without touching the online rate limiter; the README notes the limitation, but documentation does not mitigate it. Use a secret-keyed lookup tag stored separately from the database (or change the login flow to include a username and use a per-user slow password hash), and document how to rotate compromised credentials.

3. **[High] Authentication state grows without a hard bound** (`src/lib.rs:62-64`, `src/lib.rs:302-319`, `src/lib.rs:389-399`). Each distinct failed-login key retains a vector until the 15-minute purge, and every successful login adds a session for up to seven days; neither map has a size or per-user session cap. Distributed clients can grow the failure map, and a party who knows one valid phrase can create arbitrarily many live sessions within the TTL, exhausting memory. Bound both stores (including key lengths), evict old entries, and add a load test for sustained login traffic.

4. **[Medium] A stalled upstream can hold proxy requests indefinitely** (`src/lib.rs:73-82`, `src/lib.rs:510-535`). The Hyper client has no connection or response-header deadline. If the protected server accepts connections but never responds, each authenticated request retains its task/socket until the peer disconnects; an outage or abusive caller can exhaust resources. Configure connect and response timeouts, and exercise a deliberately stalled upstream in an integration test. Streaming response bodies may need a separate idle timeout rather than a total transfer deadline.

5. **[Medium] Logout is CSRF-able via a top-level GET** (`src/lib.rs:91-93`, `src/lib.rs:427-440`). `any(logout)` accepts GET and deletes the session. A third-party page can navigate an authenticated user to `/__wsb/logout`; `SameSite=Lax` still sends the cookie on top-level GET navigation. Require POST plus an origin or CSRF check, and test that GET leaves the session valid.

6. **[Medium] Database failures are silently reported as wrong credentials** (`src/users.rs:130-145`, `src/lib.rs:389-425`). `.ok()` turns any SQLite error, including corruption or an I/O failure, into `None`. The handler then tells users their phrase is incorrect, increments their failure counter, and emits no diagnostic for operators. Return a `Result<Option<User>, _>`, log errors without exposing secrets, and return a server error without consuming a failed-login attempt.

7. **[Medium] Login throttling is not atomic under concurrency** (`src/lib.rs:302-319`, `src/lib.rs:377-415`). The limit check and failure recording take separate locks, with a database lookup between them. On the multithreaded runtime, several simultaneous attempts for one key can all pass the check before any records a failure, exceeding the documented ten-attempt limit. Reserve an attempt under the same lock before lookup (or use a bounded token bucket); add a concurrent-attempt test.

8. **[Low] Upstream URLs with paths are accepted but their paths are ignored** (`src/settings.rs:89-98`, `src/lib.rs:473-482`). Configuration such as `upstream = "http://127.0.0.1:3000/app"` passes validation, yet forwarding replaces only scheme and authority, so `/foo` goes to `/foo`, not `/app/foo`. Reject non-root paths, queries, and fragments during config validation unless base-path proxying is intentionally supported; add a config test for this case.
